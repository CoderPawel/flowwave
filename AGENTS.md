# FlowWave contributor and agent rules

FlowWave is a privacy-first personal energy and focus rhythm application.
These rules apply to every change, whether written by a person or an agent.

1. This is not a medical diagnostic application.
2. Never describe calculated scores as medical diagnoses.
3. Raw health data and user behavior data are sensitive.
4. Collect only data necessary for an explicitly implemented feature.
5. Never collect window titles, URLs, document contents, messages, file names, or keystrokes.
6. Every external data source requires explicit user consent.
7. All synchronization operations must be idempotent.
8. Mobile must work offline-first.
9. Store timestamps in UTC and preserve the original timezone.
10. Every calculated recommendation must include an explanation based on input factors.
11. Never silently invent health data.
12. Missing data must be represented explicitly.
13. Do not introduce a dependency without explaining why it is required.
14. Generate production-quality code, tests, migrations, documentation, and error handling.
15. Before changing architecture, write a short decision note in `docs/architecture`.
16. Do not delete existing functionality to make a task easier.
17. Follow the existing project structure and naming conventions.
18. Return a summary of changed files and commands required to test the change.

## Where the rules are enforced in code

| Rule | Enforcement |
| --- | --- |
| 1, 2, 10 | `packages/core/src/scoring` returns a disclaimer and a per-factor explanation with every score. |
| 4, 5 | `packages/core/src/privacy` rejects payloads containing forbidden fields; `docs/privacy/data-inventory.md` lists every collected field. |
| 6 | `packages/core/src/consent` requires an active, append-only consent decision per consent type (health data per external source and scope, device usage, notifications, analytics); `apps/api/src/importedRecords` checks it through `ConsentService` before every import. |
| 7 | `packages/core/src/sync` replays results for repeated operation IDs and rejects reused IDs with different payloads. |
| 9 | `packages/core/src/time` stores UTC instant + IANA time zone + offset; naive local timestamps are rejected. |
| 11, 12 | `packages/core/src/data` models every input as `present` or `missing` with a reason; scoring never imputes values. |
| 3 (accounts) | `apps/api/src/auth` stores only Argon2id password hashes and SHA-256 token hashes; audit metadata passes the privacy guard; `apps/mobile/lib/src/features/auth` keeps tokens in native secure storage and deletes local account data at sign-out. |
| 3, 7, 8 (phone) | `apps/mobile/lib/src/core/database` refuses to open the local database unless it is encrypted; `apps/mobile/lib/src/core/sync` queues changes in the same transaction, keyed by record ID, and uploads them only while signed in; a test fails if a local column is missing from `docs/privacy/data-inventory.md`. |
| 3, 5, 7, 9, 10, 12 (database) | CHECK constraints in `apps/api/prisma/migrations` (valid zones, present-or-missing, explanations with a disclaimer, per-user foreign keys) and unique import keys used by `apps/api/src/importedRecords`; `db/tests` covers them and fails on a column with a forbidden name. |

## Conventions

- TypeScript, strict mode, ES modules. File names are `camelCase.ts`; tests live in `packages/<name>/test/<module>.test.ts` and `apps/api/test/<module>.test.ts` (the web panel keeps `<module>.test.ts` next to the module).
- Flutter code in `apps/mobile` follows Dart conventions: `snake_case.dart` files, feature first under `lib/src/features/<feature>/{domain,data,presentation}` with shared code in `lib/src/core` and `lib/src/app` ([0015](docs/architecture/0015-flutter-app-architecture.md)); tests mirror that layout under `test/`. Generated code is committed.
- API routes are versioned under `/v1`; the OpenAPI contract in `packages/contracts` is generated, never edited by hand.
- Domain errors extend `FlowWaveError` and carry a stable `code`.
- The database schema is `apps/api/prisma/schema.prisma`. Migrations live in `apps/api/prisma/migrations/<timestamp>_description/` as `migration.sql` (generated by Prisma, plus hand-written constraints) and a hand-written `down.sql`. SQL constraint tests live in `db/tests`.
- Every table and column is described in `docs/data/data-dictionary.md` and `docs/privacy/data-inventory.md`; a test fails otherwise.
- Architecture decisions live in `docs/architecture/NNNN-title.md` (see the index there).

## Commands

```bash
npm ci                      # install pinned dependencies
npm run check               # lint + strict type check + unit tests
npm run build               # build every workspace
npm run contracts:check     # OpenAPI contract matches the API
(cd apps/mobile && flutter analyze && flutter test)
```

Setup, database, and environment templates are described in `README.md`.
